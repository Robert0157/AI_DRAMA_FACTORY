| 交付項 | 複核判定 | 理由 |
|---|---|---|
| B 線 `gate_check` v2 | ✅ 實質防護 | 不只是讀布林值：逐迭代重驗（iter 檔＋L1 快照＋log＋hash 鏈＋champion 一致性）、鎖檔內容指紋（`package_sha256` 與王者/狀態雙檔比對）、離線資料 `evidence_valid=True` 但 `eligible=False`、舊格式拒絕。**信任邊界已明示**（非數位簽章、同寫入權者可偽造整套——合理）。 |

## 3. 距離「世界級產品」還差什麼（七缺口）

> 判準：世界級 = 「穩定產出**被人選中**的鏡頭、組成音畫成立的作品」，且每一次核准／失敗／重試／發布都有可信證據（v3 語）。工程可信度只是四分之一。

### G1 產能與單元經濟（最硬瓶頸）
實測：本機 Wan 2.1（1.3B, 20 步, 480p）每 4.85 秒單元 ≈ 3 小時 18 分 → 175 秒/集 ≈ 118 小時。兩頻道週更（2×175s 全本地）≈ 238 小時/週 > 168 小時物理上限。
**補法**：正式化「混合路由」產能假設——本地 Wan 承擔環境基底 ＋ VEO/Kling 承擔英雄鏡 ＋ §2.1a 變體剪輯擴充時長；先做「30 秒三軌比試」取得 P50/P95、合格率與**每秒合格素材總成本**表，再談週更承諾。

### G2 音樂驅動剪輯（A 線產品靈魂）
`librosa` 未安裝、`music_analysis.v1` 未建立——現行分鏡仍按固定單元切。**沒有音樂時間軸的 MV 產線，不可能到世界級。**
**補法**：輕量 MIR（onset／beat／能量／頻帶）→ 編譯成固定控制序列（段落→場景推進、下拍→關鍵切點）→ 帶母帶 animatic 先行（免費階段定節奏）→ 鎖時間軸再生成。與 AutoMV 局部借鏡合併為一條工作包，以盲評＋成本定去留。

### G3 同集一致性與變體 QC
I2V 首幀錨定未接線；`BASE_VARIATION_POLICY` 仍只是常數——變體清單未編譯進 locked JSON、覆蓋率未按**內容**計算（防換檔名規避）。
**補法**：`build_job` 編譯 variants＋worker manifest 記錄＋QC 以來源區段 hash 計算原生覆蓋率（≥60%）、相鄰重複檢查、每次變體具來源與轉換紀錄。

### G4 核准閉環（C-01）
Telegram 回呼無 allowlist、核准僅存記憶體、無冪等、核准與內容 hash 未綁定、發布入口未全數強制查核。
**補法**：單一核准服務（Mac 本機 SQLite **單寫**）＋ `approval.v1`（核准者／關卡／內容 hash／成本上限／過期）＋所有生成與發布入口查核；重放與換稿自動失效。

### G5 B 線內容未達閘門（平台期診斷）
forge 王者 μ8.0（第 12 迭代至今 ~182+ 迭代未被超越）——典型平台期。v3 建議「先診斷、別把迭代數當品質」正確。
**補法**：人類校準（CEO 已評樣本 ×2 集盲測 rubric）、失敗分類報告、必要的策略切換（結構級重寫／不同 beat 種子），由 CEO 決策續跑或改法。

### G6 版控・CI・還原（本輪已起步）
本輪已建立外部成果版控基線＋補入 Auto_Drama。仍缺：CI（把 `verify_dual_line_release.py` 掛進每次 push）、pre-push 保護、備份還原演練。
**補法**：最小 CI＝本地 githook 或 GitHub Actions 跑離線驗證入口（入口已現成）。

### G7 部署與發行最後一哩（C-03＋發布）
Mac 正式 worker／forge 仍是舊版；無部署窗口演練紀錄；YouTube 官方上傳鏈（§10a）未驗收；浮水印 QC 未全鏈。
**補法**：依手冊 §7「正式部署閘門」做一次完整演練（備份→部署→雙驗→受控樣片→回滾測試）；發布阻斷完成後才做上傳鏈演練。

## 4. 對 v3 提案的獨立意見

- **同意**：保留三大開源（Toonflow／LMD／ComfyUI）不換平台；「先可信交付、後強化能力」順序正確；「1,000 次是專案預算護欄、非業界標準」的修正務實；六長鏡與敘事單元解耦須 CEO 核准的定位正確；十項候選的查證尺度（不迷信宣傳）正確。
- **補充三點**：
  1. **單機全本地不可行是「產能驗收」結論**——建議把混合路由＋變體剪輯寫成正式產能假設並以 30 秒比試實測（見 G1），不要留到 175 秒才發現。
  2. **G2 的 MIR 與 AutoMV 合併試點**：先做輕量版（librosa 級），AutoMV 僅借「音樂分析→鏡頭規劃」概念，轉接器進我方 JSON。
  3. **部署前置風險**：Mac 系統 Python 3.9＋LibreSSL 的 TLS 警告會咬 C-01 外部 API 鏈——部署窗口前先建立 homebrew Python 3.12 專用 venv。
- **一處補正**：v3／手冊未把「成果未入版控」列為風險（本輪已補基線）；建議今後凡「已驗證」即日入版控，維持驗證即凍結。

## 7. 三大決策的專家建議（2026-09-13，經現場實證）

### 7.1 forge 決策 → **暫停續跑，先做平台期診斷（3 天）再重啟**
- 事實：182 輪、王者 μ8.0 自第 12 輪未被超越；候選 min 域 7.0–7.5——現行「全包稀疏 patch × 多評審噪聲」已到局部最優，續跑只燒 API 不放品質。
- 失敗類別高度重複（分弧覆蓋／伏筆配額／標注一致性／輪迴衝突）＝**規則層占多數** → 建議分流：確定性規則以結構檢查補齊；LLM 評審專注創意域（concept／character／dialogue）。
- CEO 品味槓桿已實證（Ep1 一次定向修訂即核准）：加入「人類節拍卡」回饋，勝過數十輪機器盲修。
- 診斷包：①失敗聚類報告 ②人類校準盲評（王者＋2 候選、隱藏來源）③閘門細化提案（A 維持全包 8.8；B「先行弧閘門」：Ep1–4 pilot arc ≥8.8＋bible/canon 完整即解鎖 CP-D，其餘弧續煉——屬規則修正，須 CEO 定案）④重啟策略（結構級重寫顆粒度）。
- 成本對比：診斷≈一輪迭代費用；不診斷的續跑≈每日數百次評審呼叫換 ~0 進展。

### 7.2 v3 §8 五項 → 逐項建議
1. **保留三大開源＋補可信交付：同意**；另把「採納 check-list」制度化（授權→隔離→契約測試→真實鏡頭→鎖版）。
