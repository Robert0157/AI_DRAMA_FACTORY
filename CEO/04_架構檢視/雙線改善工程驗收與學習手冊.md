# A／B 雙線改善工程驗收與學習手冊

文件日期：2026-09-13。對象：CEO、工程部、品管單位。

## 1. 驗收結論

**A 線與 B 線的全部改善尚未達成，不得簽核「整體完成」或「正式量產可上線」。**

本輪完成的是 A 線交付／恢復防護、B 線鑄造證據閘門與生成前置防護，以及可重現的雙機工程驗證。最後版本在 Windows 與 Mac 隔離環境各通過 **77 項測試，零失敗、零跳過**；兩邊受驗程式與測試的 SHA-256 一致。

這不代表音樂驅動剪輯、I2V 一致性、審核授權閉環、175 秒正式成片、每週產能及觀眾品質驗收已完成。**Mac 正式 worker／forge 尚未替換；B 線生成凍結仍有效。**

本文件是具體交接與學習文件，不是新產線規範。背景決策見 [世界級架構與雙線影像策略_v3.md](世界級架構與雙線影像策略_v3.md)；既有政策仍以 [架構說明書_v16.1.md](../../架構說明書_v16.1.md) 為準。未放寬 480p、20 步、B 線六長鏡、三關卡、母帶／原音及浮水印規範。

## 2. 改善背景與系統分析

原系統有分鏡規劃、開源工作台、影片引擎、後製工具與 CEO 檢查點，但部分規範僅存在文件或狀態欄位，尚未轉成可驗證的程式條件。

本輪選擇先修下列根因，沒有再導入一整套開源平台：
1. **信任標記而非證據**：鑄造入口只讀取核准布林值與迭代數，未重新檢查分數、作品或執行用途。
2. **生成時間與剪輯時間混用**：Wan 需要 4n+1 幀，原本向下取整讓 5 秒／20fps 變成 97 幀、4.85 秒。
3. **生成後才發現輸入不成立**：母帶沒有在昂貴生成前驗指紋與長度；B 線可能在後面的鏡頭才發現提示詞未準備好。
4. **把檔案存在當成完成**：非空檔案就能重用，缺乏輸入與媒體指紋；失敗交付仍可能出現在 done。
5. **重啟缺少外部任務身分**：本機中斷不代表 ComfyUI 任務停止，盲目重送可能重複耗用資源。
6. **工程通過與作品通過混淆**：編碼與音軌合格不代表視覺、浮水印、敘事、核准或發布條件成立。

保留 Toonflow、LocalMiniDrama、ComfyUI、現有故事室及 FFmpeg。AutoMV 等候選採納判斷仍是提案，本輪沒有宣稱已安裝、實測或整合。

## 4. 工程變更說明

### 4.1 B 線鑄造證據

程式：[script_forge.py](../../scripts/story_room/script_forge.py#L1428)。測試：[test_script_forge.py](../../tests/test_script_forge.py)。

新寫出的 `forge.lock.v2` 記錄執行模式、王者迭代與完整 canonical JSON SHA-256。驗證時不只讀鎖檔，而是比對王者劇本、最新狀態、王者評分、逐次 L1 快照與迭代紀錄。離線資料可以 evidence_valid=True，但 eligible 必須為 False。

舊短指紋仍保留在原有迭代紀錄，避免任意改寫歷史；新鎖加入完整指紋。分數依現行王者 μ 規則檢查，並容許已四捨五入單域造成的小幅加權差，不放寬最低域／總分門檻。

**信任邊界**：這是受控檔案的完整性檢查，不是防止具工作區寫入權者偽造整套證據的數位簽章；不是 CEO 身分認證，也不是端到端關卡授權。測試中的「正式模式」資料是暫存模擬，不是可供生產使用的核准。

### 4.2 A 線交付與恢復

程式：[mac_wan_worker.py](../../scripts/pipeline/mac_wan_worker.py#L146)、[dispatch_to_mac.py](../../scripts/pipeline/dispatch_to_mac.py#L109)。測試：[test_mac_wan_worker.py](../../tests/test_mac_wan_worker.py)。

母帶在生成前驗證，封裝前再驗一次，避免漫長生成期間音樂被替換。模型請求向上取合法幀數；Stage 1 使用固定時間軸裁切並編成一致 H.264，Stage 2 仍採 concat demuxer 無損拼接。最終音訊明確裁到已驗證影像長度，不再由 `-shortest` 靜默決定片長。

技術 QC 包含精確影格數與全檔解碼；每個新快取附輸入及媒體指紋。生成任務另有 `.task.json` 紀錄 prompt_id、request hash、狀態及更新時間。請求已發出但回應遺失時標記結果不明，後續自動執行不得再次提交。

CLI 的 watch、once、job 都必須先排除既有 worker，再持有 OS 檔案鎖執行回收。OS 鎖由行程結束釋放，保留 `.worker.lock` 檔案本身不是殭屍鎖，也不應在服務執行時刪除。

**限制**：直接匯入 RenderWorker 的其他程式仍應持有同一把鎖；本輪驗證的是正式 CLI 路徑。模型檔案目前以名稱參與請求，權重內容完整鎖定仍是待辦。所有技術通過工件都保留發布待審標記，不能把 done 當成正式批准。

### 4.3 B 線生成前置檢查

程式：[lmd_video_chain.py](../../Auto_Drama/auto_drama/lmd_video_chain.py#L43)。測試：[test_lmd_video_guards.py](../../Auto_Drama/tests/test_lmd_video_guards.py)。

先檢查整集每鏡提示詞與權威參考圖，再送出第一個影片請求。新生成鏡頭提交前再次比較前檢快照。缺詞、無 token、越界 token 或缺圖都應回開發階段處理，不得臨時改詞後繼續量產。

**限制**：此處是同一執行內的提示詞／參考 URL 檢查，不驗證 URL 背後圖片位元組，也不取代 CP-D／CP1 的持久內容鎖。B 線舊影片快取的來源指紋與完整影音驗收仍須另外完成。

## 6. 品管重現指南

先取得本輪完整程式與測試，不可只複製單一入口。確認 `WORKSPACE_ROOT` 指向待驗工作區且有寫入權；使用已驗證的 Python 環境，PATH 必須找得到 ffmpeg、ffprobe。不要對正式資料庫執行修復或測試資料灌入。

Windows，在工作區根目錄執行：

```powershell
.\venv\Scripts\python.exe scripts/maintenance/verify_dual_line_release.py
```

Mac，在隔離驗證包根目錄執行：

```bash
PATH="/opt/homebrew/bin:/usr/local/bin:$PATH" WORKSPACE_ROOT="$PWD" /usr/bin/python3 scripts/maintenance/verify_dual_line_release.py
```

入口程式：[verify_dual_line_release.py](../../scripts/maintenance/verify_dual_line_release.py)。每次建立新的證據目錄，不覆寫舊結果；如指定 `--output`，路徑必須位於 WORKSPACE_ROOT 內且尚未存在。

本輪版本應看到：

```text
77 passed
ENGINEERING_QA=PASS PRODUCTION_RELEASE=BLOCKED
```

**退出碼 0 只代表這組工程測試通過，不是批准生產或發布。** 若測試數少於基準 77、FFmpeg 缺失造成跳過、測試失敗、沒有 JUnit、測試期間來源改動，或必要媒體工具不可用，都不得簽核工程通過。

品管須查核：
1. JSON counts 與 JUnit 一致，failures／errors／skipped 均為 0。
2. source_sha256 與受驗版本一致，sources_unchanged_during_tests=True。
3. 原始 stdout／stderr 存在；警告需分類，不能只看綠字。
4. synthetic FFmpeg 測試確實執行，不能以 mock 全部取代媒體測試。
5. 測試的核准樣本僅在暫存目錄；不得移成正式 lock_ready 或批准影片生成。
6. 工程簽核與作品／成本／發布簽核分開填寫。

## 7. 遷移與故障處理

### 舊資料相容性

- 舊 `lock_ready` 缺 v2 證據時預設拒絕。不得手動補 eligible、複製模擬測試資料或自動重新加分來通過；應在受控流程重審，並保留既有 CEO 凍結劇本文字。
- 舊非空影片快取沒有輸入／媒體指紋時拒絕。保留原檔供對照，由工程確認來源再安排核准的重生；不要整批刪除舊素材。
